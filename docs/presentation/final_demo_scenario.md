## 핵심 기능 1: 자연어 예약 챗봇 데모

### 데모 입력 예시 (Happy Path)

**Step 1 — 슬롯 탐색:**
```
사용자 입력: "이번 주 SEM 2시간 연속 슬롯 찾아줘"
```

**예상 출력:**
```
🔍 SEM 장비에서 2시간 연속 가용 슬롯을 찾았습니다!

  1. 5월 22일 (목) 09:00 ~ 11:00
  2. 5월 22일 (목) 14:00 ~ 16:00
  3. 5월 23일 (금) 10:00 ~ 12:00

원하시는 시간대를 선택해주세요.

[슬롯 선택 버튼 3개 표시]
```

**Step 2 — 슬롯 선택 (버튼 클릭):**
```
사용자 동작: [1. 5월 22일 (목) 09:00 ~ 11:00] 버튼 클릭
```

**예상 출력:**
```
✅ SEM 예약이 완료됐습니다!

📅 일시: 5월 22일 (목) 09:00 ~ 11:00
🎯 목적: 연구 목적
🔖 예약 ID: #7

캘린더 탭에서 예약을 확인하실 수 있습니다.

[메시지 버블에 "✅ 예약 완료 — 캘린더 탭에서 확인하세요" 배지 표시]
```

**Step 3 — 캘린더 확인:**
```
동작: 상단 탭에서 "캘린더" 클릭
→ FullCalendar에 SEM 예약이 표시됨
```

### 백업 데모 (API Key 없는 경우 — Mock 모드)

위 Happy Path와 완전히 동일하게 동작합니다.
`.env`에 `LLM_MOCK_MODE=true` 설정 시 Claude API 없이 자동 슬롯 탐색 및 예약 생성.

---

### 데모 중 설명 포인트

1. **"자연어 파싱"**: "SEM", "2시간", "이번 주"를 LLM이 추출하는 것을 설명
2. **"슬롯 탐색 알고리즘"**: 기존 예약 충돌 확인 + 연속 슬롯 탐색 로직
3. **"DB 저장"**: 예약 ID와 함께 Reservation 테이블에 저장됨을 Swagger에서 확인 가능
4. **"캘린더 연동"**: FullCalendar.js로 시각화

## 핵심 기능 2: AI 매뉴얼 챗봇 (RAG) 데모

### 데모 준비 (발표 시작 전)

```
① "매뉴얼 챗봇" 탭 클릭
② SEM 장비 선택
③ ⚙️ 관리 버튼 클릭
④ [데모 매뉴얼 등록] 버튼 클릭 (내장 SEM 매뉴얼 텍스트 인덱싱)
⑤ "✅ SEM 데모 매뉴얼이 등록됐습니다!" 메시지 확인
```

### 데모 입력 예시 1 (시료 준비)

```
사용자 입력: "SEM 측정 전 시료 준비 조건이 뭐야?"
```

**예상 출력:**
```
SEM 시료 준비를 위한 핵심 조건을 안내드립니다.

1. 전도성 확보: 시료는 반드시 전도성이 있어야 합니다. 비전도성 
   시료는 금(Au) 또는 백금(Pt) 스퍼터 코팅이 필요합니다.

2. 코팅 두께: 5~10 nm 권장

3. 시료 크기 제한: 최대 30mm × 30mm, 두께 10mm 이하

4. 안전 주의: 고전압(최대 30kV) 사용 장비이므로 안전 교육 
   이수 후 사용해주세요.

📚 참고 출처:
1. SEM 운영 매뉴얼 (데모) — p.1, 청크 #0 (유사도: 0.8234)
2. SEM 운영 매뉴얼 (데모) — p.1, 청크 #1 (유사도: 0.7891)

🔧 (Mock 임베딩 모드 — 실 배포 시 OpenAI text-embedding-3-small 사용)
```

### 데모 입력 예시 2 (진공 펌핑)

```
사용자 입력: "진공 펌핑 절차 알려줘"
```

**예상 출력:**
```
SEM 진공 펌핑 절차입니다.

1. 시료 홀더에 시료를 고정합니다.
2. 시료 챔버에 시료 홀더를 삽입합니다.
3. 챔버 문을 완전히 닫습니다.
4. PUMP 버튼을 눌러 진공 펌핑을 시작합니다.
5. 진공도가 5×10⁻³ Pa 이하가 될 때까지 대기합니다.
   (소요 시간: 약 10~15분)

📚 참고 출처:
1. SEM 운영 매뉴얼 (데모) — p.1, 청크 #1 (유사도: 0.8012)
```

### 데모 입력 예시 3 (다른 장비 — 매뉴얼 없는 경우)

```
사용자 동작: AFM 장비 선택
사용자 입력: "AFM 측정 방법 알려줘"
```

**예상 출력:**
```
⚠️ AFM 장비의 매뉴얼이 아직 등록되지 않았습니다.
관리자가 PDF 매뉴얼을 업로드하면 이 장비에 대한 질문에 답변드릴 수 있습니다.
```

---

### 데모 중 설명 포인트

1. **"RAG 파이프라인"**: PDF → 청크 → 임베딩 → FAISS → 검색 → LLM 의 6단계 흐름
2. **"출처 투명성"**: 답변 하단에 어느 페이지, 몇 번째 청크에서 가져왔는지 표시
3. **"벡터 유사도"**: 질문과 매뉴얼 청크의 코사인 유사도 점수 표시
4. **"Mock 모드"**: API Key 없이도 전체 파이프라인이 동작하는 데모 가능성 강조
5. **"장비 격리"**: 장비별 별도 FAISS 인덱스로 교차 검색 방지

## 실패 대비 Mock 시나리오

### 백엔드가 완전히 다운된 경우

발표 슬라이드로 대체:
1. **기능 1** — 시퀀스 다이어그램 + 코드 라인별 설명 (chat.py)
2. **기능 2** — RAG 파이프라인 다이어그램 + 코드 라인별 설명 (rag_service.py)

### 인터넷이 없어서 API 호출 불가한 경우

`.env`에서:
```
LLM_MOCK_MODE=true
RAG_MOCK_MODE=true
```
→ 두 설정만 있으면 모든 데모가 오프라인으로 동작합니다.

### DB가 비어있는 경우 (장비 없음)

Mock 응답은 SEM(ID:2) 기준으로 하드코딩되어 있어 DB에 장비가 없어도 슬롯 탐색 시연 가능.

## 교수님 예상 질문 & 답변 가이드

**Q: RAG에서 어떻게 관련 내용을 찾나요?**
A: "사용자 질문을 1536차원 임베딩 벡터로 변환하고, FAISS IndexFlatIP로 코사인 유사도를 계산합니다. 상위 5개 청크를 Claude에 context로 제공합니다."

**Q: 챗봇이 틀린 답변을 할 수도 있지 않나요?**
A: "RAG의 핵심은 hallucination 방지입니다. LLM에게 '매뉴얼 내용만 기반으로 답변하고, 없으면 없다고 말하라'는 시스템 프롬프트를 적용했습니다."

**Q: Mock 모드와 실제 모드의 차이가 있나요?**
A: "파이프라인 구조는 완전히 동일합니다. 임베딩만 해시 기반 Mock 벡터로 대체되므로, 의미적 유사도 계산 정확도는 낮아지지만 모든 API 호출과 DB 저장은 실제로 동작합니다."

**Q: 기존 예약 시스템과 새 기능이 충돌하지 않나요?**
A: "RAG 매뉴얼 챗봇은 완전히 분리된 DB 테이블(manual_documents, manual_chunks, manual_qa_history)과 라우터(/api/v1/manuals)로 구현되어 기존 코드에 영향을 주지 않습니다."

## 향후 확장 기능 (발표 마무리용)

1. **자동 사용 로그 고도화**: 체크인/아웃 자동 감지 + 사용 패턴 분석

5. **이메일/Slack 알림**: 예약 확인, 안전 교육 리마인드 자동화
